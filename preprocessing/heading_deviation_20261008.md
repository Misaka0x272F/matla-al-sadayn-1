# matla-al-sadayn-1：G0「标题层级数量不守恒」10 条的根因与裁定

**登记日期**：2026-10-08　**状态**：已知偏差，**保留已发布译文**，未做源侧修复

## 一、结论先行

这 10 条**不是译文缺陷，也不是本次 CLI 改动引入的回归**，而是
**源侧结构整备脚本 `normalize_structured.py` 的缺陷**被一个新增判据首次照出来。

判据本身是对的（标题层级必须守恒），**修书不如修脚本**；但修脚本要重建 `structured/`，
会改动 ch01–ch10 的块边界，须重跑对照表——属独立的一次整备，不在本次交付范围内。

---

## 二、根因

`preprocessing/tools/normalize_structured.py:121`：

```python
if len(s) <= 55 and not any(b in s for b in _HEADING_BAD):
```

升为标题的三个前提是「独占一行」「以关键词开头」「**长度 ≤55 字符**」。

本书的年份标题在数字版（قائمیه اصفهان 2013）里与条目标题**被连成一行**，例如

```
وقایع سنه ثمان و خمسین و سبعمائه ذکر عزیمت پادشاه جانی بیک به آذربایجان     ← ≈66 字符
└──────── 年份标题（回历 758 年之事）────┘└──────── 条目标题 ────────┘
```

该行 66 字符 > 55 ⇒ `_classify` 返回 `body` ⇒ 年份标题留在段落中间，
**没有被切成独立的 `##` 行**。

短年份标题（`## وقایع سنه خمس و اربعین و سبعمائه`，≈32 字符）不受影响，所以是
**约一半命中、一半漏切**的间歇性缺陷。

### 规模

| | 数量 |
|---|---|
| 源文年份标题合计 | **46** |
| 已被切成 `##` | 23 |
| **被黏在段落中间（漏切）** | **23** |
| 译文呈现的年份标题 | **23** |

漏切分布：ch01×2、ch02×1、ch03×4、ch04×3、ch05×2、ch06×4、ch07×3、ch08×2、ch09×1、ch10×1。

「feat(nav): 单元内子标题锚点目录 + 标题层级保真/守恒」。

`released=true/ok`）。2026-10-07 的「构建器修复后全库复查」（工作区提交 `96e3cde`）
第一次让该判据跑到这本书上，才暴露出这 10 条。

**判据是新增的，缺陷是既有的，只是此前无人检查。**

## 四、10 条偏差的三个具体成因

G0 只比对**各层级标题的数量**（`count_heading_levels`），不比对标题身份，
所以这 10 条数字背后是三类不同的事：

### 1. `### اشاره` → `## 按语` 的 h3→h2 提升（8 个单元）

front-preface、ch03、ch06、ch07、ch08、ch09、ch10（以及 ch05）各有一处把首条
`### اشاره`（按语）提升成 `## `。

**这是上面根因的连锁后果**：ch06–ch10 在 `structured/` 里一个 `##` 都没有
（年份标题全被黏住），译者为了让目录不从 h1 直跳 h3，把首条 h3 提到 h2。
属于**内容中立的层级归一**，不增不减任何文字。

### 2. ch06 新增一个源侧没有的年份标题

译文 `translation/body/ch06.md:163`：

```
## 回历 760 年之事——Amir Adil Ghazghan 被杀
```

`structured/` 中没有对应标题（回历 758 的年份标题在 `structured/body/ch06.md:15`
是段落内的一整行，未被切成 `##`）。译文据此**还原**了年份小节。

⚠ **该标题插在句子中间**：其上一行译文是
「…Amir Ghazghan 于 Salisar 骑马赴 Qushlamishi 时，Qutlugh—」，
句子被标题劈成两半。这是全批最刺眼的一处呈现问题。

### 3. ch07 少渲染一个标题

源 `structured/body/ch07.md:291`

```
### ذکر توجه سلطان جلال الدین شاه شجاع به جانب افغان و جرون
```

（记 Jalal al-Din Shah Shuja 转向阿富汗与杰龙）在译文中**无对应标题**；
其正文**已在译文 `translation/body/ch07.md:295` 译出**（"遂向阿富汗与热地之众进发…"），
只是并入了上一条、未单独成标题。

**内容不缺，只是标题没渲染。**

## 五、成品层面的实际影响

读者在成品里看到的是**年份小节标题的不一致**：

| 章 | 覆盖年份 | 译文年份标题 |
|---|---|---|
| ch01–ch05 | 717–757 | 有（基本齐全） |
| ch06 | 758–763 | 仅 760 一个（且插在句中） |
| ch07–ch10 | 764–771 | **没有** |

即「前几章有年份导航、后几章没有」。**年份信息本身在正文里都在，没有丢内容**，
属结构呈现层面的不一致，而非信息缺失。

## 六、本次裁定与理由

**保留已发布译文，登记为已知偏差，不改 `structured/`、`translation/`、`align/`、成品 EPUB。**

理由：

1. 本书 2026-09-29 已交付并附 CC BY-SA 许可，属**已发布**成果；
2. 缺陷在源侧脚本，**不在译文**——为迁就脚本缺陷去改译文是改错对象；
3. 修脚本必然要重建 `structured/`，ch01–ch10 的块边界随之改变，
   必须重跑 `assemble → make_align → import` 并同步 `.tr`。
   这正是 `AGENTS.md` 记录的**「块级错位是本项目最危险的缺陷」**那一类操作，
   不应与一次交付审计混在一起做；
4. 因此**本书维持不放行**（`released=false / structure_open`）——
   门禁在这里报出是对的，不应为了放行而给结构门开豁免口子。

> 术语门有 `preprocessing/terminology_exemptions.csv` 豁免机制，
> **结构门没有**，且不应为单本书新增——那会把一个真实的源侧缺陷永久掩盖成「已知豁免」。
