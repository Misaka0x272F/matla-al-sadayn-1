### 1.1 RTL 阻塞与修复（本次关键工作）

PyMuPDF 对 RTL **按视觉 x 从左到右**输出 span/line → 词序颠倒；文本含呈现形字符
（U+FB/FE）与双向控制符（U+202A–E）。原 CLI 无任何 RTL 处理，直接抽取会得到倒序乱文。

**已修复**（CLI `feat/rtl-extraction` 分支，`src/auto_epublizer/ingest/rtl.py`）：

- 书级 RTL 判定（`pdf.rtl=auto|on|off`，前 20 页预扫描）+ 行级守卫；
- 逐行：剥双向控制符 → NFKC 归一化 → RTL 主序行 token 逆序（逻辑序还原）；LTR 行不动；
- 新增 `fa` langprofile、分句标点 `؟ ؛ ۔`、词数统计纳入阿拉伯字母系；
- 验证：`tests/test_rtl.py` 8 例 + `scripts/verify_rtl_pdf.py`（pdftotext oracle），
  本书词序一致率 **95.7%**（残差为行/段切分差异与少量嵌入阿拉伯引文），386 tests 全绿，
  LTR 抽取零改动。

## 3. 语义整备（`tools/normalize_structured.py`，确定性）

源数字版把每张**印刷页的书名页眉**内联进正文（约每半页一次），并混入三类噪声。
确定性清洗规则（只搬运、不做语义判断，留痕 `repairs.jsonl`）：

1. 去数字版页眉（y<35 且含 `Ghaemiyeh`/`صفحه`/`مرکز تحقیقات`）：249 处；
2. 去印刷版书名页眉（含书名 + `ص` + 数字）：420 处；
3. 去分隔线（纯 `_` 行）：11336 处；
4. 块内硬换行按标点/字数上限（600 字）拼段；标题（关键词+短行）、诗体标签
   （`نظم/بیت/مصرع`）、编者注释（`N) …`）断为独立段。

**编者注释策略（重要，影响翻译口径）**：本书脚注是 1974 年校勘本的现代编辑层
（异文 `ك/س/ع/ف` + 书名页眉引用），**不拆分、保留原位、随正文一起翻译**（用户决定全量译）。
清洗后 `verify_structured.py` 逐物理行守恒自查：**7334/7334 行无缺失**。
